# Правила совместной разработки

## Роли

ChatGPT — Game Director / Game Designer / Reviewer.

Codex — Lead Developer.

Game Director принимает решения по:

- геймдизайну;
- механикам;
- экономике;
- карте;
- визуальному направлению;
- приоритетам разработки.

Codex отвечает за:

- реализацию;
- архитектуру кода;
- поиск технических ошибок;
- тестирование;
- технические улучшения, не меняющие задуманный геймдизайн.

## Перед каждой задачей

1. Прочитать `tasks/CURRENT_TASK.md`.
2. Определить, какая документация из `docs/` относится к задаче.
3. Прочитать эту документацию.
4. Изучить существующий код, связанный с задачей.
5. Только после этого начинать реализацию.

Не нужно каждый раз читать абсолютно всю документацию, если она не относится к задаче.

## Во время разработки

- Не менять утверждённый геймдизайн самостоятельно.
- Если технически лучше сделать иначе, чем указано Game Director, не менять решение молча — отметить предложение в `tasks/LAST_REPORT.md`.
- Не переписывать работающие системы без необходимости.
- Стараться делать системы модульными, чтобы последующее развитие игры не требовало полного переписывания кода.
- Не начинать следующий этап разработки самостоятельно.

## После каждой задачи

Проверить выполненную работу доступными средствами:

- TypeScript;
- build;
- lint, если будет настроен;
- тесты, если будут настроены;
- очевидные runtime-проблемы.

Исправить ошибки, относящиеся к выполненной задаче.

После этого обновить `tasks/LAST_REPORT.md`.

Формат `tasks/LAST_REPORT.md`:

```md
# Последний выполненный этап

## Что сделано

## Изменённые/созданные файлы

## Технические решения

## Проверки

Что запускалось и с каким результатом.

## Остались проблемы

## Требуется решение Game Director

Если решений не требуется — написать «Нет».

## Предложения Codex

Только действительно полезные предложения. Не менять игру самостоятельно.
```

## Документация

Если во время задачи принято новое долгосрочное техническое решение, обновить соответствующий файл в `docs/`.

Не записывать туда временные детали и мелкие изменения.

Документация должна отражать актуальное состояние проекта.

## Git

После полностью завершённой и проверенной задачи:

1. Проверить `git diff`.
2. Убедиться, что случайные или лишние файлы не попали в commit.
3. Сделать понятный commit.
4. Отправить commit в `origin/main`.

Не делать push незавершённого или явно сломанного состояния, если Game Director прямо этого не попросил.
