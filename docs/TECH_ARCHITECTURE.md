# Техническая архитектура

## Текущее состояние

Репозиторий содержит запускаемый playable core vertical slice на Phaser + TypeScript. Реализован один полный цикл: найти питомца, украсть его, уйти от погони или быть пойманным, доставить питомца на базу и получать тестовый пассивный доход.

Прототип использует только программно созданную временную графику. Финальных игровых ассетов нет.

## Ключевые технологии

| Технология | Версия | Назначение |
| --- | --- | --- |
| Phaser | 4.2.1 | игровой runtime, рендеринг, ввод, Arcade Physics |
| TypeScript | 7.0.2 | строгая типизация исходного кода |
| Vite | 8.2.0 | dev-сервер и статическая production-сборка |
| npm | версия среды | зависимости и scripts |

Требование Vite к Node.js: `^20.19.0` или `>=22.12.0`.

## Сборка

- `npm run dev` — локальный Vite dev-сервер.
- `npm run typecheck` — `tsc --noEmit`.
- `npm run build` — typecheck и production-сборка Vite.
- `base: './'` позволяет использовать результат как статическую сборку.
- Серверная логика отсутствует.
- `node_modules/`, `dist/`, логи и временные файлы исключены через `.gitignore`.

## Сцена и композиция

`WorldScene` — единственная игровая сцена вертикального среза. Она отвечает за создание и связывание модулей, настройку коллизий и камеры и покадровый вызов систем, но не содержит реализацию всех механик внутри одного класса.

Основной игровой сценарий координирует `CoreLoopSystem`. Состояния вертикального среза:

- `SEEK_PET`;
- `ESCAPE`;
- `INCOME`.

Состояния питомца хранятся отдельно:

- `AT_NPC_BASE`;
- `FOLLOWING_PLAYER`;
- `AT_PLAYER_BASE`.

Состояния NPC-владельца:

- `IDLE`;
- `CHASING`;
- `RETURNING`.

## Мир и карта

- Размер Arcade Physics world: 3840 × 2560 px.
- Временная карта программно строится `WorldBuilder`.
- Координаты прототипной планировки отделены в `data/worldLayout.ts`.
- Мир включает пять цветовых зон, дороги, воду, мост, базы, здания, деревья, кусты и ворота.
- Вода, здания, крупные деревья и ворота используют статические Arcade Physics bodies.
- В воде оставлен физически проходимый разрыв под мостом.
- Границы физического мира не позволяют игроку и NPC выйти за карту.
- Depth персонажей и подходящих объектов основан на координате Y для top-down псевдо-3D.

Точные координаты являются prototype layout и не утверждают финальный дизайн карты.

## Player

`Player` инкапсулирует:

- Arcade Physics body;
- движение;
- нормализацию диагонального направления;
- последнее направление;
- dash, cooldown и trail;
- world bounds;
- визуальную ориентацию и Y-depth.

Технические значения вертикального среза:

- обычная скорость: 230 px/сек;
- скорость dash: 590 px/сек;
- длительность dash: 170 мс;
- cooldown dash: 900 мс.

Значения вынесены в `config/gameplay.ts` и не являются финальным балансом.

## Input

`InputController` объединяет desktop и mobile input и возвращает сцене единый `FrameInput`.

Desktop:

- `WASD` и стрелки — движение;
- `Space` — dash;
- `E` — contextual interaction;
- `F2` — debug overlay.

`VirtualControls` реализует без сторонних библиотек:

- joystick слева;
- dash-кнопку справа;
- contextual touch-кнопку кражи;
- независимое владение joystick конкретным pointer ID;
- отображение готовности и восстановления dash непосредственно на mobile-кнопке;
- пересчёт позиций после resize/orientation change.

В Phaser настроены три активных указателя (`input.activePointers: 3`), поэтому joystick можно удерживать одним пальцем, одновременно нажимая dash или contextual interaction вторым.

Touch UI включается для coarse-pointer/touch устройств. Параметр `?touch=1` используется для технической проверки.

## Pet

`Pet` отвечает только за собственное состояние и представление:

- idle-анимацию;
- плавное следование по небольшой истории реально пройденного игроком маршрута;
- повышенную скорость догоняния;
- безопасную коррекцию к точке маршрута при слишком большом отставании;
- размещение на NPC-базе или базе игрока;
- Y-depth.

`PlayerPathHistory` хранит только ограниченный массив breadcrumb-точек без игровых объектов. Питомец последовательно проходит эти точки с задержкой, поэтому при обычном движении повторяет путь игрока вокруг воды, зданий и крупных препятствий. Navmesh и тяжёлый pathfinding не используются.

Pet не управляет погоней или экономикой.

## NPC и погоня

`OwnerNpc` реализует движение владельца и его локальные состояния.

`ChaseSystem` запускает и останавливает погоню, обновляет преследование и проверяет поимку.

Технические значения вертикального среза:

- скорость погони NPC: 226 px/сек;
- скорость возвращения: 185 px/сек;
- дистанция поимки: 45 px;
- head-start после кражи: 900 мс;
- grace period после провала: 1600 мс.

NPC использует прямое Arcade Physics-преследование. Маршрут между двумя базами спроектирован открытым; сложный pathfinding и navmesh не используются.

## База

`BaseSystem` знает только геометрию delivery zone и позицию питомца после доставки. Он проверяет совместное попадание игрока и следующего питомца в зону доставки.

База игрока является безопасной зоной в рамках vertical slice: успешная доставка завершает активную погоню и отправляет NPC домой.

## Экономика

`EconomySystem` не зависит от UI. Он хранит деньги и суммирует независимые источники дохода.

После доставки прототипной Собаки регистрируется источник `+1 монета/сек`. Это `TECHNICAL PROTOTYPE VALUE`, а не утверждённый баланс.

## UI

`Hud` показывает:

- целое количество денег;
- суммарный доход в секунду;
- текущую цель;
- готовность dash;
- contextual prompt;
- короткие сообщения об успехе или провале;
- отключённый по умолчанию debug overlay.

HUD использует `scrollFactor(0)` и перестраивается по размеру viewport.

Desktop HUD показывает отдельную верхнюю полосу dash cooldown. В mobile-режиме эта полоса скрыта, а cooldown отображается затемнением и восстанавливающимся кольцом непосредственно на кнопке «РЫВОК». Панели цели и денег используют отдельную компактную раскладку для узких экранов.

## Временная графика

Все изображения создаются средствами Phaser:

- `Graphics`;
- геометрические Game Objects;
- текст;
- программно созданные текстуры персонажа, NPC и Собаки;
- простые тени, depth, trail и celebratory-эффекты.

Внешние графические ассеты не используются.

## Debug и QA

- `F2` включает FPS, координаты игрока и состояния питомца/погони.
- `?dev=1` включает отдельную dev-only панель для ускоренной проверки core loop.
- Debug выключен по умолчанию и не участвует в обычном интерфейсе.
